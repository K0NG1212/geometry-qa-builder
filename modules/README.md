# Builder v0.2 模块边界

本版是项目内 RUNBOOK + 提示词 + Python 程序，**没有安装全局 Skill**，不需要 API。
AI 步骤由当前 Codex 会话执行；Python 本身不调用订阅模型。相同提示词不保证相同结果。

| 模块 | 执行者 | 输入 → 输出 | 失败如何定位 |
|---|---|---|---|
| M0 范围配置 | 人/助手 + 程序 | 题量上限、能力和数据范围 → run 配置快照 | 初始化报错；分类取舍仍需研究判断 |
| M1 材料整理 | 程序 + 来源检查 | 原文/XYZ → bundle + asset-units | 空文本、坏结构、单位来源缺失 |
| M2 证据提取 | AI + 引用检查 | bundle → evidence | 格式、假引文、缺资产；语义支持需审核 |
| M3 任务模板 | AI + 关联检查 | evidence → tasks | 不存在的证据、缺输入、不可执行验证 |
| M4 构题与计算 | AI 计划 + 可信程序 | construction plan → qa | 原子编号、单位、容差；数值由程序生成 |
| M5 质量筛查 | AI + 程序 | qa + 原始证据 → review | 字段、覆盖、错误标记；同一会话不是独立审核 |
| M6 导出与记录 | 程序 | 完整运行 → 候选输入、私有答案、质量报告 | 未完成不能导出；不自动纳入正式 benchmark |

材料准备沿用 builder.py prepare。新版从 pipeline.py init 开始。
在每个 run 中保存材料、提示词、格式、程序、单位来源和哈希。
next 只生成当前模块请求包；accept 才验证并提交。通过的阶段默认复用。
无效结果保存在 attempts-v02；前序阶段不受影响。修正当前输出后重新 accept。
要改已通过的阶段，用 fork --before；要改变提示词/程序/规则，修改项目版本后 init 新 run。
自动检查的通过标准只能覆盖其明确声明的范围，不能作为科学质量保证。

支持的计算器：XYZ 两点距离、三点夹角。尚未实现：自动检索、OCR/多模态解析、
通用设计评分器、多论文批调度、专家审核界面、跨论文去重/防泄漏划分和模型难度评测。
先测试各模块的失败边界，再以真实材料小批验证。不要把软件 fixture 算成研究样本。
